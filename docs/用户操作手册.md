# A 股量化研究平台：界面与操作手册

> 当前产品边界以 [`current-system.md`](current-system.md) 和 [`current-data-gaps.md`](current-data-gaps.md) 为准；旧的多市场、approved 和正式发布描述不适用于当前公开数据研究模式。

这是项目唯一面向使用者的说明。它按页面的阅读顺序讲解，不要求你懂模型、代码或量化交易。

> 平台使用免费公开数据进行收盘后研究。所有概率、收益区间和风险等级均为研究观察：**非实时、非投资建议、不可直接交易**。

## 先理解系统在做什么

选择一只股票或 ETF 后，平台先回答三件事：

1. 当前数据和证据够不够用；
2. 经营质量、成长稳定性、估值位置、股东回报和主要风险如何；
3. 哪些证据支持或反驳当前观察，接下来应该关注什么。

未来 1 日、5 日和 20 日的方向、收益区间与回撤只在“专业详情”中作为辅助短周期诊断展示，不能替代长期判断。

系统显示“证据不足，暂不判断”时，是保护机制正常工作，不是页面错误。

## 1. 启动网页

第一次使用，在项目根目录安装依赖：

```bash
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install --upgrade pip
python3 -m pip install -e ".[dev,documents,train]"
npm install
```

启动本地平台：

```bash
npm run dev:research-platform
```

终端会显示实际地址，通常为：

- 工作台：<http://127.0.0.1:5173>
- 开发 API 文档：<http://127.0.0.1:8000/docs>

若 5173 被占用，请使用终端打印的新端口。停止服务时，在启动它的终端按 `Ctrl+C`。

## 2. 页面顶部：先确认研究边界

第一次打开先看顶部：

| 页面内容 | 含义 |
| --- | --- |
| `A 股研究模式` | 默认模式；可以做公开数据研究、训练、推理和 Shadow 验证 |
| `research_pit` | 历史数据可用于研究，但不能证明正式生产级可见时间 |
| `strict gate` | 数据异常或输入条件不足时，系统会拒绝输出结论 |
| `中文 / English` | 可切换界面语言，浏览器会记住选择 |
| 正式模式 `blocked` | 缺少授权数据、SLA 与正式 PIT 证据；这是正确状态 |

正式模式是未来能力，不影响 A 股研究模式的正常使用。

## 3. 选择研究对象

在左侧“研究对象”区域：

1. 输入证券代码或名称；
2. 点击股票或 ETF 卡片；
3. 选中卡片高亮后，中央区域会加载该对象的研究信息；
4. 若没有历史研究记录，页面会提示需要先运行研究更新。

当前主线是 A 股日线和少量宽基 ETF。页面中兼容保留的“持仓”“添加资产”等控件不连接交易，不管理真实资金。

## 4. 中央研究区：从上到下阅读

### 4.1 研究摘要

研究摘要显示当前是收盘确认研究还是盘前研究、数据截至时间，以及“研究级公开数据”的提醒。

若显示“等待快照”，说明该标的尚未完成当前数据冻结；此时不要解读预测卡片。

### 4.2 数据质量与资格

这一块回答“结果是否有足够的公开数据覆盖和可追溯来源”。

| 字段 | 通俗解释 |
| --- | --- |
| 覆盖率 | 需要的行情和特征中，实际拿到的比例 |
| 缓存状态 | 数据是否新鲜；过期数据会触发拒答 |
| 事件状态 | 公告和事件源是完整、部分可用还是不可用 |
| 数据降级原因 | 例如来源失败、价格不一致、历史状态无法证明 |
| Provider | 数据来自 AKShare 或 Baostock，是否发生主备切换 |

免费数据存在缺口时，平台会显示 `degraded`、`partial` 或 `abstain`，不会把缺失数据伪装成正常数据。

### 4.3 四项研究任务

方向、收益与风险互相独立，不能相互替代：

| 卡片 | 正确理解 | 不应理解为 |
| --- | --- | --- |
| 1 日方向 | 下一有效交易日上行、下行、横盘的研究概率 | “明天一定涨/跌” |
| 5 日方向 | 未来 5 个有效交易日的方向概率 | 交易建议 |
| 20 日收益区间 | P10、P50、P90 三个可能收益区间 | 保证收益或目标价 |
| 20 日最大回撤风险 | 未来 20 日显著回撤的风险概率 | 下跌概率 |

任务卡会显示状态和模型版本。普通使用时只需看结果状态和简短原因；点击卡片才展开模型与快照证据。

### 4.4 “证据不足，暂不判断”是什么意思

系统拒答时，优先看卡片上的原因。常见情况：

| 原因类别 | 表示什么 |
| --- | --- |
| 数据过期或覆盖不足 | 当前公开数据不适合输出研究观察 |
| 不同来源不一致 | 公开源的价格、交易日或成交量有冲突 |
| 输入超出训练范围 | 当前市场情况和模型训练样本差异太大 |
| 模型分歧过大 | 候选模型的结论明显不同 |
| 模型或报告缺失 | 对应任务尚未完成训练或证据校验 |

正确操作是等待下一次收盘后更新，或在研究详情中查看具体原因；不要把 `abstain` 当作下跌，也不要根据空卡片做判断。

## 5. 模型状态：只需记住五种

| 页面状态 | 含义 | 应如何使用 |
| --- | --- | --- |
| `research_only` | 基于公开数据的研究结果 | 可以观察、比较和复盘 |
| `exploratory` | 产物已生成，但严格研究指标未全部通过 | 仅作实验观察 |
| `unavailable` | 缺少模型、报告或必要数据 | 不显示概率，查看原因 |
| `abstain` | 数据或模型不适合输出结果 | 暂不判断 |
| `blocked` | 正式模式条件缺失 | 不影响研究模式 |

所有免费数据产物固定为：

```text
data_tier=research_pit
status=research_only
deployment_ready=false
```

这说明系统不会把免费研究数据包装成正式投资预测服务。

## 6. Shadow 前向验证：结果以后会怎样

历史回测只说明过去；Shadow 会把当天研究预测冻结，未来再用真实结果验证。页面会显示：

- 已冻结：保存了多少次不可修改的研究预测；
- 有效：其中多少次通过当天的数据质量门禁；
- 暂不判断：多少次系统主动拒答；
- T+1 / T+5 / T+20 / T+60：多少条预测已到可以回填的交易日；
- 20 日报告与 60 日主模型复核：前向验证是否积累到相应阶段。

Shadow 数量少表示前向证据还在积累，不代表系统可以跳过验证或直接进入正式发布。

## 6.1 系统什么时候更新模型

你不需要每天手动训练，也不需要每天等待复杂模型重算。平台按四个节奏运行：

- **每日收盘后**：更新公开数据、冻结当天快照，生成研究读数并冻结 Shadow；当天数据不会立即被当成训练标签。
- **每周**：检查数据覆盖、来源切换、特征缺失、漂移、校准误差和拒答率；异常时只创建训练建议，不直接换模型。
- **每月**：只用已经成熟的未来窗口重建样本，按固定时间滚动、purge/embargo、最终留出和 OOF 校准训练候选模型。
- **每季度**：重新检查研究池、标签和特征，并运行 MLP、TCN、PatchTST、iTransformer challenger。

候选模型要通过数据、泄漏、hash、留出、分组稳定性和至少 60 个独立有效 Shadow 交易日后，才可能成为新的研究主模型。20 个有效 session 只用于生成第一份前向报告，不足以更换主模型。替换会保留旧版本，出现退化可以回滚。所有这些动作仍然是研究模式：`research_pit / research_only / deployment_ready=false`，不会自动产生实盘信号。

查看自动更新状态时，使用页面的“研究自动更新”卡片，或访问后端接口：

```text
GET /api/v1/research-lifecycle/status
```

接口返回最近数据日期、下次训练、当前候选、替换/回滚状态和阻断原因。若状态显示“等待成熟样本”或“Shadow 不足”，表示系统在按规则积累证据，不是程序卡死。

## 7. 中英文切换

点击顶部 `中文` 或 `English` 即可切换。

- 核心研究页面、任务卡、状态标签、数据质量和 Shadow 文案会随语言变化；
- 证券代码、模型名、hash、Provider 名称和后端原因代码保持原样，便于追溯；
- 若某个技术原因仍为英文，先看卡片上的摘要；该原文用于证据追溯，不是用户结论。

## 8. 运行一次研究更新

完整入口：

```bash
python3 scripts/run_cn_research_demo.py
```

它会依次完成：

```text
公开数据采集
→ 数据质量审计
→ Research PIT 快照
→ 四项任务训练与评估
→ 研究模型清单
→ 研究推理
→ Shadow 冻结
→ 后端验收报告
```

第一次建议先运行轻量 smoke，确认环境和网络：

```bash
python3 scripts/run_cn_research_demo.py \
  --profile smoke \
  --max-symbols 20 \
  --max-equities 20 \
  --minimum-equities 1 \
  --minimum-cohort-symbols 1 \
  --minimum-history-sessions 60 \
  --symbols-per-cohort 1 \
  --skip-sequence-challengers
```

完成后可查看：

```text
artifacts/cn_research_demo/latest.json
artifacts/cn_research_demo/latest-backend-acceptance.json
```

报告为 `partial` 不一定是程序错误。公开源限流、历史不足或模型未通过门禁时，系统应如实显示不可用或拒答。

## 9. 常见问题

### 页面没有显示概率

- `unavailable`：尚无对应任务模型或报告；
- `abstain`：系统主动拒绝输出；
- `blocked`：当前查看的是正式模式；
- `research_only`：可查看研究结果，但不能用于交易。

不要把空结果当作 0%，也不要用其他任务的结果代替它。

### 为什么正式模式不能用

免费 AKShare/Baostock 数据不能证明商业授权、SLA、完整历史可见时间和正式 PIT revision。正式模式必须保持阻断。

### 怎样确认代码正常

在项目根目录运行：

```bash
python3 -m pytest -q
npm test -- --run --no-file-parallelism
npm run build:workbench
git diff --check
```
