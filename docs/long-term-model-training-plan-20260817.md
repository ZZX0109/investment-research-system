# 长期研究模型：自动化实验实施计划（2026-08-17）

## 目标与边界

本计划是 2026-08-17 的执行记录，当前事实源以 [`current-system.md`](current-system.md) 和 `config/long_term_training.yaml` 为准。当前四项主任务固定为未来 120/240 个交易日的相对宽基超额收益与最大回撤；长期波动和基本面质量持续性只能作为独立评分卡或候选实验，不得替换四项主任务。系统不是买卖模型，输出只可使用“值得进一步研究”“中性观察”“风险较高”“证据不足，暂不判断”。

`direction_1d`、`direction_5d`、`return_20d`、`drawdown_20d` 被保留为折叠的市场观察；它们不进入主模型特征、标签、排序、模型选择或评分卡融合。

## 数据与门禁

1. 数据落地到新的 staging 目录，保留原始来源、数据快照 ID、SHA-256 和数据截止时间。
2. 执行 PIT/生命周期/历史成分股/宏观发布时间审计。财报必须有 `available_at` 或实际公告时间；其余无法证明当时可得的数据均为未知。
3. 正式全量训练只在审计全部通过后开始。审计失败时，仅允许 dry-run、合成测试和研究代码检查；不得写入 `active.json`，不得覆盖既有模型。
4. 每个样本必须满足：股票（不是 ETF）、当日已上市且可交易、非停牌/涨跌停/ST/退市状态、历史股票池成员关系可证实、所需标签已成熟。不能证明的状态一律排除，不填零。

## 标签与切分

| 任务 | 标签定义 | 主指标 |
|---|---|---|
| 相对表现 120d/240d | 股票区间收益减去决策当日匹配宽基基准的同期收益；仅在股票横截面内排序 | Rank IC、ICIR、Top/Bottom 分组成本后超额收益 |
| 下行风险 120d/240d | 从决策日后的可交易价格路径计算最大回撤 | 回撤 MAE、风险分层召回、尾部风险识别 |
| 长期波动（候选） | 未来 120d/240d 实现波动或下行波动 | 仅候选实验，不进入当前四项主任务 |
| 质量持续性（评分卡/候选） | 后续 4/8 个 PIT 季度的盈利、现金流、杠杆和盈利能力稳定性 | 仅独立评分卡或候选实验，不替换主任务 |

- ETF 只用于基准、市场状态和风险特征，绝不与 162 只股票混合排名。
- 以季度快照为主；每个快照仅使用当时已公开资料。
- 最终 holdout 为最近 8 个成熟季度，完整隔离，只评估一次。
- 开发期使用 24 季度训练窗口 + 4 季度验证窗口的扩展/滚动 walk-forward；240 日标签要求至少 240 个交易日 purge，并在边界后额外 embargo 120 日。实际代码使用两者中更严格者，避免标签窗口交叠。

## 候选模型顺序

1. 行业中性历史均值/中位数基线；
2. Ridge 与 Elastic Net（便于解释）；
3. LightGBM/XGBoost 多任务或每任务单独模型；
4. 只有第 3 步在隔离 holdout 稳定通过后，才训练 StockMixer、MASTER 等面板深度候选模型。

复杂模型必须同时优于简单模型的长期排序、回撤识别、概率校准和跨阶段稳定性，才有资格作为候选；单段收益更高不构成晋级理由。

## 自动化与断点续跑

| 阶段 | 产物与恢复点 | 允许并发 |
|---|---|---|
| A 数据审计与快照 | `snapshot.json`、输入 SHA-256、PIT 审计 | CPU 多进程 |
| B 特征/标签预计算 | 分区 Parquet、每日期分区完成标记 | CPU 多进程，单写入者 |
| C 基线与消融 | 每任务/每折 `stage.json`、模型、OOF 预测 | CPU 并行，受 RAM 限制 |
| D 深度候选 | 每 epoch checkpoint、optimizer、RNG、数据分片索引 | GPU0 串行；CPU 预取并行 |
| E 评估与模型卡 | 不可变 holdout 报告、校准、弃权统计、SHA-256 | CPU 并行 |

所有状态文件采用临时文件后原子替换。重启同一 `run_id` 时：先验证输入快照/代码/配置哈希；一致则跳过已通过 SHA 校验的阶段，不一致则只使受影响的下游阶段失效。失败阶段保留日志、checkpoint 与失败原因，绝不覆盖既有通过模型或 `active.json`。

## 资源策略（仅 GPU0）

高利用率的目标是减少空转，而不是人为占满资源。季度级 162 股票的树模型样本量有限，强行使用 GPU 不会更快；GPU0 应集中留给深度面板候选模型。

- 固定 `CUDA_VISIBLE_DEVICES=0`，不使用 GPU1；深度阶段同一时间只运行一个 GPU 进程。
- 先探测可用 RAM 与 GPU 显存，自动选择批大小；以目标 75–90% 显存占用为上限，遇到 OOM 自动回退一档批大小并从上一个 checkpoint 续跑。
- 特征及标签按日期批量预解码到内存映射/Parquet 缓存；DataLoader 使用 `pin_memory`、持久 worker、预取队列。CPU worker 数取 `min(可用逻辑核-2, 16)`，并把 `OMP_NUM_THREADS`、`MKL_NUM_THREADS` 限制在剩余核数，避免过度竞争。
- 机器 RAM 的 60–75% 用作只读特征缓存上限，保留系统与写入余量；内存压力上升时自动降为分区流式读取，不交换到磁盘。
- 基线树模型占用 CPU 阶段可以与 GPU0 的数据加载/评估重叠；绝不同时启动多个争抢 GPU0 的训练。
- 每 30 秒记录 CPU、RAM、GPU 利用率、显存、吞吐、阶段和 ETA；持续低 GPU 利用率先查数据加载、批大小和 CPU 预处理，不盲目增大模型。

## 弃权与展示

任一条件满足即 `ABSTAINED`：关键 PIT 未验证、评分卡完整度 <80%、数据截止时间异常、关键证据冲突、输入超出训练分布、预测不确定性过高、模型间分歧超过阈值、样本资格不成立。

展示同时给出正反证据、主要风险、后续观察指标、推翻当前判断的条件、适用周期、数据截止时间与“仅供研究参考，不构成投资建议”。专业因子、短期观察和概率数字默认折叠。

## 建议执行顺序

1. 上传完成后，在 staging 上运行只读数据审计与 dry-run；
2. 修复审计发现的 PIT、状态、历史成分股、宏观发布时间缺口；
3. 生成冻结数据快照后运行基线与消融；
4. 通过预设门槛后，串行运行 GPU0 深度候选；
5. 只读最终 holdout，生成模型卡、审计包和前端评分卡；
6. 质量门禁全绿后，人工确认候选快照；本计划本身不激活任何快照。
