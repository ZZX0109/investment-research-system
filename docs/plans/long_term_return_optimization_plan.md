# 长期相对收益预测专项优化计划

> 范围：比赛项目的研究展示。目标是提高未来 240 个交易日相对收益的**横截面比较能力**，不承诺收益，不生成买卖指令，也不在本计划中启动训练、改动服务器或下载数据。
>
> 口径：只在股票横截面内学习和评估；ETF 仅作为宽基基准、市场状态和风险特征，绝不进入股票排名或收益标签。

## 1. 当前结论与本轮目标

已完成的真实深度实验给出的结论是：

| 任务 | 当前观察 | 在系统中的定位 |
| --- | --- | --- |
| 120 日相对超额收益 | 最好 Rank IC 约 0.015，接近无稳定排序信号 | 默认折叠的辅助观察，不再投入大规模搜索 |
| 240 日相对超额收益 | StockMixer 的 Rank IC 约 0.205，为现有收益候选中最好；其他候选与精调结果有明显波动 | 本计划唯一收益主任务，必须以重复 walk-forward 验证确认 |
| 120/240 日最大回撤 | 风险排序显著强于收益排序（约 0.61 / 0.55） | 作为收益模型的辅助任务和前端风险说明，不能替代收益结论 |

本轮不追求把所有模型跑得更久，而是验证下列问题：**240 日 StockMixer 信号是否在不同时间段、行业和随机种子下仍然存在，且是否超过简单基线。** 若答案是否定的，比赛版本保留“长期风险较高/中性观察/证据不足”等研究结论，而不把收益分数包装为可靠预测。

## 2. 数据与标签改造（优先级 P0）

### 2.1 固定样本资格

每个样本为“股票 + 决策日”，只保留当日已上市、可交易、非停牌、非涨跌停限制、非 ST、未退市，且 240 日标签路径完整的股票。ETF、不可交易股票、标签未成熟样本不参与损失、排名或指标计算；它们不能用零值或前值填充伪装为正常样本。

决策时点的股票池、行业分类、证券状态、财报和事件均采用当时可获得版本。无可靠可用时间的字段记为未知，不默认解释成“没有事件”。

### 2.2 240 日主标签与对照标签

冻结一个主标签，同时在开发集比较两个对照版本；最终只能选择一个版本进入候选模型。

| 标签 | 定义 | 用途 |
| --- | --- | --- |
| `excess_return_240d_benchmark` | 个股从决策日后首个可交易价格到 240 日终点的总收益，减同期匹配宽基基准收益 | 主标签；保留现有可比性 |
| `excess_return_240d_industry_neutral` | 上述主标签减同日、同历史行业中股票的稳健中心值；行业样本过少时标记未知而非回退到全市场 | 检查信号是否只是行业轮动 |
| `excess_return_240d_risk_adjusted` | 主标签除以前置窗口估计的波动或下行波动，并对极端值裁剪 | 检查是否只挑选高波动股票 |

所有收益标签在**每个决策日的股票横截面内**按训练窗口统计量做 winsorize（建议 1%/99%）和标准化。统计量只能由对应训练折计算；验证、holdout 不得参与阈值估计。标签尾部、可交易掩码和基准缺失都要单独记录数量。

120 日收益只保留为诊断任务：若在同一方案下仍没有稳定正 Rank IC，不再为其扩展超参数搜索。

## 3. 特征分组与消融（优先级 P0/P1）

每组先独立接入，再按“基础 + 单组”的方式与冻结基线比较；不允许只汇报全量特征中最好的结果。每一折均输出覆盖率、时效性和缺失原因，防止缺失本身变成股票优劣标签。

| 顺序 | 特征组 | 主要内容 | 预期作用 |
| --- | --- | --- | --- |
| P0-A | 价格、流动性与风险 | 多窗口动量、反转、波动、成交、换手、流动性 | 提供已验证可用的时序基础 |
| P0-B | 相对强弱与市场状态 | 宽基/行业相对收益、市场宽度、波动状态；ETF 仅作为外生特征 | 剥离市场共同波动和行业轮动 |
| P1-A | 估值与质量 | PE/PB/PS/FCF 收益率历史分位、ROE/ROIC、利润率 | 为 240 日估值回归和质量溢价提供信息 |
| P1-B | 增长、现金流与负债 | 收入/利润/现金流趋势，应收、存货、杠杆、偿债压力 | 降低“账面增长”造成的假信号 |
| P1-C | 行业与公司事件 | 行业景气、公告后变化、减持/质押/监管等可验证事件 | 解释跨行业差异和尾部风险 |
| P2 | 宏观 | 利率、汇率、信用和发布时间明确的宏观变量 | 只在覆盖完整后比较其增益 |

建议的消融顺序为：`A` → `A+B` → `A+B+估值质量` → `A+B+财务` → `A+B+事件` → `全量`。只有某组在至少 60% 开发折中改善主指标，才保留；否则从候选特征集中移除并保留失败记录。

## 4. 模型、损失与集成（优先级 P1）

### 4.1 必须保留的简单基线

同一份切分和特征口径下至少比较：

1. 行业中性历史均值/中位数；
2. Ridge/Elastic Net；
3. LightGBM 或同级树模型；
4. 当前 StockMixer；
5. MASTER（市场引导面板对照）。

当前脚本中的 StockMixer/MASTER 采用日期 batch 和分位数损失，这是正确的面板输入基础；但对收益排序仍不够直接。不得仅因深度模型复杂而淘汰树模型。

### 4.2 收益专项损失

按以下顺序实施并在相同数据、相同 fold 下比较：

1. 现有分位数回归（基线）；
2. 稳健回归损失（Huber / clipped MSE），减少极端收益支配；
3. **日期内 pairwise 排序损失**：仅对同一决策日、均可交易的股票两两比较，按收益差设置权重；
4. 回归 + 排序混合损失，例如 `0.5 × Huber + 0.5 × rank loss`；
5. 多任务损失：主头预测 240 日相对收益，辅助头预测 240 日最大回撤与长期波动。辅助风险损失初始权重不高于主收益损失的 0.3，并在开发折消融确认其帮助后才保留。

排序损失不使用跨日期样本对；每日期股票数不足最小阈值（建议 20）时跳过该日期的排名损失并记录原因。

### 4.3 候选结构与集成

StockMixer 是第一优先候选，围绕 `20/60/120` 日输入窗口、`128/256` 隐层、轻度 dropout 和市场/行业输入分别试验。MASTER 作为第二面板候选；PatchTST、TCN、iTransformer 只保留一个与 StockMixer 相同口径的复核配置，避免再次进行全模型网格搜索。

只允许在开发期 OOF 预测上学习集成权重，并冻结权重后评一次 holdout。优先考虑 3 个随机种子的同构 StockMixer 均值；若其优势不稳定，则退回单模型。不得基于 final holdout 调整模型、特征、权重或阈值。

## 5. Walk-forward、评估和晋级门槛（优先级 P0）

### 5.1 时间划分

- 最后 252 个成熟交易日为完全隔离的 final holdout，使用一次；其最后 126 日作为 holdout 内压力切片。
- 开发期采用扩展或滚动 walk-forward：初始训练至少 504 日、验证 126 日；240 日标签的训练样本标签终点必须早于验证起点，并在边界加入 240 日 purge + 至少 20 日 embargo。
- 由于 240 日标签和 holdout 会显著消耗可用日期，若当前历史不足以形成至少 3 个有效开发折，则只扩充历史/快照后再进行大规模调参；不得把无效折换成随机切分。
- 归一化、缺失值处理、行业中性化、特征选择和集成权重均在每个训练折独立拟合。

### 5.2 开发期晋级门槛

以下门槛是资源分配条件，不代表收益承诺：

| 条件 | 进入下一阶段的最低要求 |
| --- | --- |
| 排序能力 | 平均 Rank IC ≥ 0.03，且至少 60% 有效开发折为正 |
| 相对基线 | 相比最强简单基线的平均 Rank IC 增益 ≥ 0.01，或 Top-Bottom spread 有一致增益 |
| 稳定性 | 3 个种子中至少 2 个为正，且没有单一行业/单一年份贡献全部效果 |
| 可交易性 | Top-K 相对基准表现扣除保守成本后不为负；报告换手和覆盖率 |
| 风险约束 | 高预测收益组不能以显著更差的 240 日回撤为代价；否则仅输出“高波动观察” |

final holdout 仅对开发期胜出的 1–2 个候选评估。若 holdout Rank IC ≤ 0、成本后 Top-K 无优势或分层稳定性失败，收益输出降级为“证据不足，暂不判断”，而不是继续根据 holdout 反复调参。

## 6. 分阶段实验队列与优先级

| 阶段 | 内容 | 预计试验数 | 进入条件 |
| --- | --- | ---: | --- |
| 0（P0） | 标签审计、三种 240 日标签、样本资格与基线重跑 | 6–9 | 数据快照和有效 fold 数确认 |
| 1（P0） | 特征 `A`、`A+B`、`A+B+估值质量` 的 Ridge/LightGBM/StockMixer 消融 | 18–27 | 每组开发期记录完整 |
| 2（P1） | StockMixer 窗口/隐层/稳健损失筛选，单 seed | 12–18 | 阶段 1 选出最佳标签和特征集 |
| 3（P1） | Pairwise 与混合排序损失、风险多任务消融 | 8–12 | 阶段 2 有正向、稳定候选 |
| 4（P1） | 3 seed 复核、MASTER 对照、OOF 集成 | 9–15 | 阶段 3 至少一个候选通过门槛 |
| 5（P2） | 一次 final holdout、模型卡和比赛展示产物 | 1–2 | 只限冻结候选 |

预计总量为 **54–83 个试验单元**，但采用条件队列：前一阶段无候选通过即停止后续 GPU 搜索，输出失败结论和风险模型结果。相较于无差别深度模型调参，这会优先把 GPU 时间花在最可能改善 240 日排序的问题上。

## 7. GPU0、CPU 和内存利用策略

- 固定 `CUDA_VISIBLE_DEVICES=0`，一时刻只运行一个深度训练进程；GPU1 不参与。
- 树模型与特征预计算使用 CPU，可与 GPU0 训练的只读准备阶段错峰，但不得争抢同一缓存写入目录。
- 将完成 PIT 过滤、特征编码后的日期分区样本缓存到本地系统盘/内存映射；DataLoader 使用 pinned memory、持久 workers 和预取。GPU 利用率长期偏低时，依次检查缓存命中、batch 大小、worker 数和数据转换，而非盲目扩大模型。
- CPU worker 建议为 `min(逻辑核 - 2, 16)`；BLAS/OMP 线程与 worker 总数协调，避免过度订阅。RAM 缓存上限为可用 RAM 的 60–75%，保留写 checkpoint 和系统余量。
- 深度阶段以 75–90% GPU 显存为目标区间；OOM 时只降低当前 trial 的 batch size，再从已保存 checkpoint 续跑。CPU/RAM/GPU 利用率、显存、吞吐、缓存命中和 ETA 每 30 秒写入 JSONL。

## 8. 断点续跑与产物规则

每个 trial 使用不可变的 `run_id / task / label_version / feature_set / model / seed / fold` 路径，保存：

- 输入快照、样本资格统计、数据/特征/标签/切分 SHA-256；
- 每折 OOF 预测、模型、训练日志和评价 JSON；
- 深度训练的 epoch checkpoint（模型、optimizer、scheduler、随机数状态、已完成 epoch、数据分片索引）；
- 资源监控 JSONL 与失败原因；
- 最终模型卡（候选数量、选择依据、已知局限、数据截止时间）。

所有 JSON 和缓存写入采用临时文件后原子替换。重启时先比对输入哈希：完全匹配则跳过校验通过的 fold/trial 并从最近 epoch 恢复；哈希变化时只失效依赖该输入的下游产物。失败、跳过和未满足门槛的产物必须保留，不能覆盖现有模型或 `active.json`。

## 9. 比赛版本的落地原则

比赛前端默认展示长期研究状态、主要支持/反方证据、长期回撤风险、数据完整度、适用周期和数据截止时间。只有通过上述开发与 holdout 门槛的 240 日候选，才能显示为“相对表现潜力”的辅助排序；否则显示“证据不足，暂不判断”。

无论结果如何，不展示目标价格、收益保证、建议仓位或直接买卖指令。当前最可靠的功能仍是长期回撤风险分层；收益模型的优化目标是让相对比较更稳健，而不是制造确定性结论。
