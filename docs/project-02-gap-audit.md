# Investment Research 投研 Demo 与 Project-02 蓝图差距审计

版本时间: 2026-07-02

对比对象:

- 当前项目: `investment-research-system`
- 参考蓝图: `project-02-ai-test-officer/project-implementation-blueprint.md`

## 1. 当前 project-01 完成状态

project-01 已从静态前端 Demo 升级为一个可运行的“个人持仓驾驶舱 + 单标的投研 Agent”原型。

已完成:

- 前端: Vite + React + TypeScript 仪表盘。
- 后端: FastAPI 服务。
- 数据库: SQLite，默认路径 `data/investment_research.sqlite3`。
- 数据源策略: 美股/ETF 优先 `yfinance`，A 股/基金优先 `AkShare`，失败时使用带时间戳的缓存/样例数据。
- 投研证据类型:
  - `market_data`: 行情数据
  - `financial_report`: 财报数据
  - `news_event`: 新闻事件
  - `historical_analogy`: 历史类比
  - `model_inference`: 模型推断
- 证据元数据:
  - `sourceType`
  - `sourceName`
  - `sourceUrl`
  - `observedAt`
  - `validUntil`
  - `confidence`
  - `isModelInferred`
  - `supersededBy`
  - `archivedAt`
- 过期机制: 过期证据归档到 `experience_history`。
- 历史情景模块: 展示过去三年类似阶段的后续 1 周、1 月、3 月收益率和最大回撤。
- 多模态投研卡片: 文档解释 + 证据表格 + 图表。
- 用户偏好: 均衡、稳健、成长、短线、基金。
- 风险控制: 页面保留“不构成投资建议”，历史类比不作为预测。

当前可演示闭环:

1. 用户打开持仓驾驶舱。
2. 系统展示组合指标、风险雷达、行业/主题暴露。
3. 用户选择偏好。
4. 用户点击单个标的。
5. 系统展示该标的的多模态投研卡片、证据链、历史相似情景和经验历史池。
6. 后端可通过 `/api/watchlist` 添加观察标的，并加载三年日线样本。

## 2. 与 project-02 蓝图的结构对比

project-02 blueprint 的目标是“提交前代码变更质检 Agent”，核心闭环是:

1. 读取 diff / PR。
2. 解析变更意图。
3. 生成结构化风险清单。
4. 生成测试策略。
5. 自动执行测试并采集结果。
6. 用 LLM Judge 输出风险报告。

project-01 当前对应关系:

| project-02 蓝图能力 | project-01 当前对应能力 | 当前差距 |
| --- | --- | --- |
| 输入 diff / PR | 输入持仓/标的/偏好 | 已有领域等价输入，但还缺正式“研究目标输入框” |
| 解析变更意图 | 解析标的、市场、偏好、持仓暴露 | 有初步解析，但主要是规则与样例数据 |
| 结构化风险清单 | 证据链、风险雷达、反方观点和研究质量审稿 | 已有，但缺统一 risk schema 和风险评分解释 |
| 生成测试策略 | 生成历史情景与观察建议 | 投资场景等价能力已有，但还缺“观察计划/提醒规则”结构化输出 |
| 自动执行测试 | 自动拉取/生成行情、证据、历史情景 | 有数据执行链路，但真实 API 成功率和日志记录不足 |
| 采集 artifacts | 图表、表格、证据记录、经验池 | 有展示 artifacts，但缺可下载报告和运行日志 |
| LLM Judge 归因 | Research Quality Judge 审稿 Agent | 已有规则版审稿维度，真实 LLM Judge 和 claim-level 归因仍待接入 |
| 可重复报告 | 页面展示 + SQLite 数据 | 可复现性部分具备，缺 run_id、报告模板、实验日志 |

结论: project-01 在“用户可见 Demo”和“金融产品表达”上进度更快；project-02 蓝图在“工程闭环、验收标准、执行日志和报告可追溯性”上更成熟。

## 4. 最大差距

### 4.1 缺少运行记录与 run_id

project-02 强调同一输入结果可重复且可追溯，保留 artifacts 和时间戳。project-01 当前只有证据记录，没有完整的“本次投研任务运行记录”。

建议新增:

- `research_runs`
  - `run_id`
  - `symbol`
  - `preference`
  - `started_at`
  - `finished_at`
  - `data_status`
  - `risk_score`
  - `summary`
- 每次调用 `/api/research/{symbol}` 生成或引用一个 run。

### 4.2 缺少正式报告模板

project-02 明确要求一页摘要和详细报告。project-01 当前只有页面展示，不能导出。

建议新增:

- Markdown 报告接口: `/api/reports/{symbol}.md`
- 报告结构:
  - 一页摘要
  - 证据链
  - 历史情景
  - 风险触发条件
  - 反方观点
  - 免责声明

### 4.3 缺少真实 Agent 分工过程

README 设计了行情与资讯收集 Agent、财务数据分析 Skill、策略回测 Skill、观察池管理 Agent、信号提醒 Agent、报告生成 Agent、LLM Judge 审稿 Agent。当前后端已有规则版 pipeline，后续仍需接真实 LLM 和工具调用 trace。

建议新增页面模块:

- 行情与资讯收集 Agent: 拉取行情、资讯、公告入口和证据时间戳。
- 财务数据分析 Skill: 解析财报/研报表格候选指标。
- 策略回测 Skill: 计算历史类比和样本外风险提示。
- 观察池管理 Agent: 管理持仓、证据有效期和经验历史池。
- 信号提醒 Agent: 生成触发器和提醒状态。
- 研究报告生成 Agent: 汇总卡片。
- LLM Judge 审稿 Agent: 审研究质量、证据支持度和事实/推断边界。

第一版可以先用规则模拟每个 Agent 的状态和输出，后续再接 LLM。

### 4.4 缺少定时巡检

project-02 有执行引擎意识；project-01 当前“每日巡检”只是展示文案。

建议新增:

- `POST /api/refresh/daily`
- 遍历 holdings/watchlist。
- 检查过期证据。
- 刷新行情。
- 归档旧推断。
- 生成新风险摘要。

比赛 Demo 可手动点击触发，不一定真的跑 cron。

### 4.5 历史情景算法仍偏演示

当前历史价格由后端生成样本路径；真实数据加载入口存在，但历史情景算法还没有严谨使用估值、财报日期和新闻情绪。

建议升级:

- 真实三年日线优先来自 yfinance/AkShare。
- 财报日期单独入库。
- 新闻事件只存摘要和时间。
- 相似度至少由四个特征组成:
  - 20 日涨幅
  - 估值分位
  - 是否处于财报前窗口
  - 新闻热度/事件数量

## 5. 相比 project-02 的优势

project-01 也有自己的优势，不是单纯落后。

- 场景更贴近普通用户，视觉展示比代码质检更直观。
- 图表、持仓、证据、历史类比天然适合比赛演示。
- 金融方向的“证据链 + 风险边界”讲法清晰，容易和普通聊天机器人拉开差距。
- 当前已经有可运行前后端，而 project-02 目前主要是 blueprint。
- 前沿研究文档已经形成，可支撑答辩中的“为什么这么设计”。

## 7. 答辩表述建议

可以这样讲 project-01:

> 我们不是做一个股票问答机器人，而是做一个可追溯的个人投研工作台。系统把行情、财报、新闻、历史类比和模型推断分开记录，每条信息都有来源、时间、有效期和置信度。过期信息不会删除，而是进入经验历史池用于复盘。历史相似情景只展示风险分布，不作为确定性预测，避免把 AI 包装成荐股工具。

如果评委问和工程闭环的差距:

> 当前版本已经完成可演示闭环，但距离生产级系统还需要补研究运行日志、报告导出、定时巡检和更严格的真实数据质量验证。我们已经按代码质检 Agent 的思路，把下一步拆成 run_id、artifacts、Judge、report 四个工程模块。

## 8. 当前结论

project-01 已基本完成我们讨论的核心目标:

- 有真实闭环架构。
- 有前沿研究痛点文档。
- 有证据链和时间戳。
- 有过期归档和经验池。
- 有多模态投研卡片。
- 有历史情景检索。
- 有用户偏好。
- 有五个核心模块的第一版表现。

本轮已补齐 project-02 式工程闭环中的三个关键短板:

1. `research_runs`: 每次投研接口调用生成 `run_id`、风险评分、开始/结束时间和数据状态。
2. Markdown 报告导出: `/api/reports/{symbol}.md` 输出一页摘要、证据链、历史情景和免责声明。
3. 手动巡检执行器: `POST /api/refresh/daily` 遍历观察池，刷新行情，检查过期证据并归档经验池。

仍需继续增强:

1. 更真实的历史数据接入，当前历史情景仍以结构化样本为主。
2. 测试脚本和可重复验收记录。
3. 真实 LLM Judge 与更细的 Agent 中间过程展示。

因此当前状态可以定义为:

> 可演示原型完成，关键工程闭环已补第一版，下一轮重点是提高真实数据质量和自动化验收。
